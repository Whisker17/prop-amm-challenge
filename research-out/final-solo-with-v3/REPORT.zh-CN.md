# Oracle-aware AMM 曲线对比 benchmark 结果

## 实验设置

- 模拟次数：1000
- 每次步数：10000
- seed 范围：起始 0，步长 1（所有策略共用同一批 seed，逐 seed 配对对比）
- 对手方：无（solo 模式，全部零售流量进入被测曲线）
- 统一初始状态：fair price = 100，reserveX = 100，reserveY = 10000
- 手续费：全部被测曲线为零手续费（DODO `lpFeeRate = 0`，Flashbots 原生无手续费，Uni V2 fee = 0）
- Oracle：每步 `fair_price = price.step()` 后量化一次为 WAD，同一个 `priceWad` 发布给 DODO（`i`）与 Flashbots（`multX`，`multY = 1e18`）
- 并行 worker：14
- 耗时：2634.1 秒
- 生成结果的 benchmark commit（**二进制的** commit，不是写报告时的 HEAD）：`26fe1f1b651c3b93d91cce954919f1eb0016efcc`，provenance 一致。

## 范围界定

本 benchmark 只对比曲线报价本身（curve-only）。池级别的风控与准入不在范围内，也未被实现：Flashbots 的 targetY emergency lock（`_isTargetYLocked`，仅作用于 swap 路径，upstream 的 quoteXtoY / quoteYtoX 本身也不经过它）、Mantle 的 notional / reserve / inventory deviation 上限、以及余额与授权检查，全部不参与。

## 运行健康检查

- 曲线 revert 次数：0（报价数学在整个运行中没有触发 revert 分支）
- `curve_reverts` 只统计被移植的**报价函数**在非退化输入下走到 revert 分支（溢出 / 下溢 / 除零）的次数。它为 0 表示定价数学在整个运行中没有触发 revert，**不等于**一笔完整的链上 swap 会成功——池级别的风控、余额与授权检查不在本 benchmark 范围内。

### 优势拆分：oracle 系统性优势 vs 曲线形状差异

锚点取「曲线形状在期初库存处与零手续费恒定乘积重合」的两条 oracle-aware 策略：DODO `K = 1e18`（PMM 的恒定乘积特例）与 Flashbots `concentration = 1`（`reserveX == targetX` 时虚拟报价储备等于真实储备）。`quote-matrix` 显示它们在该点与 Uni V2 报价逐位一致。于是：

- **oracle 系统性优势** = `均值(锚点 − UniV2)`：曲线形状在期初相同，剩下的就是「按 oracle 重新定价」这件事本身带来的差异。
- **曲线形状差异** = `均值(策略 − 锚点)`：oracle 相同，剩下的就是曲率参数带来的差异。
- 两者之和恒等于 `均值(策略 − UniV2)`（同一批 seed 上配对差的均值是线性的）。

> 该拆分锚定在**期初库存**。它不表示 oracle-aware 曲线在其它点上等于恒定乘积——价格一动，锚点会重定价而被动恒定乘积不会。只有均值可拆，分位数不可拆，因此不做拆分。

## 说明

- edge 一律从 AMM 角度、按外部 fair price 计价：正值表示 AMM 获利。
- `arbitrageEdge` 通常为负（AMM 向套利者付出），`arbitrageLoss = max(0, -arbitrageEdge)`。
- `netEdge = retailEdge + arbitrageEdge`。
- 曲线内部全部使用整数定点数（uint256）运算；`f64` 只出现在 oracle 量化与模拟账本边界。
- `curve_reverts` 只统计被移植的**报价函数**在非退化输入下走到 revert 分支（溢出 / 下溢 / 除零）的次数。它为 0 表示定价数学在整个运行中没有触发 revert，**不等于**一笔完整的链上 swap 会成功——池级别的风控、余额与授权检查不在本 benchmark 范围内。
- Uni V2 不消费 oracle 价格，这是该曲线本身的性质，作为无 oracle 基准列出。
- `positiveNetRate` 是该策略自身 netEdge 为正的 seed 占比，**不是**与另一条曲线的比较；跨曲线比较一律看配对统计一节的 paired win rate。
